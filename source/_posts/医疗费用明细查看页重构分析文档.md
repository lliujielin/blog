## 1. 文档概述

本文档详细说明 **N042001.vue** 页面的业务定位、核心流程、功能能力、技术实现亮点、AngularJS 重构价值、现存技术问题以及阶段性优化方案，可用于项目复盘、技术评审、版本迭代与代码交接维护。

**基础信息**

- 页面名称：医疗费用明细查看
- 页面编号：N042001
- 技术栈：Vue 2.5、Vue Router、HSA UI、Webpack 4、Canvas API
- 页面定位：医疗费用 OCR 识别结果人工复核工作台
- 重构背景：由 AngularJS 存量页面渐进式迁移至 Vue 技术栈，实现现代化组件化改造

## 2. 页面业务定位

页面采用行业标准的**左图右表工作台布局**，左侧展示报销材料原图，右侧展示结构化费用明细数据。面向审核人员提供票据对照、数据修正、明细管理、结果导出、任务完结全流程能力。

页面核心业务价值并非简单的图片预览与表格编辑，而是打通图像识别与结构化数据的联动校验链路，形成闭环复核体系：

```
报销材料图片 → OCR 识别坐标 → 费用结构化数据 → 人工复核修正
```

依托图像坐标映射与实时联动能力，解决传统人工复核“看图、查表、校对反复切换”的低效问题，提升医保票据审核精准度与作业效率。

## 3. 核心业务流程

1. 页面从路由参数解析受理单号 `reimAcpId`、图片 ID `imageId`，作为核心业务入参；

2. 调用图片查询接口，获取当前受理单下所有报销材料图片及对应材料类型；

3. 自动按照发票、明细、病历、其他材料四类完成分类，生成缩略图导航列表；

4. 根据当前选中图片 ID，加载对应费用明细数据与 OCR 原始识别坐标；

5. 监听表格行悬停、点击事件，匹配对应图像坐标，在原图叠加高亮区域，实现图文联动对照；

6. 支持人工编辑费用项目名称、单价、数量，系统自动按照公式重算金额，保留两位小数；

7. 提供明细新增、删除、批量保存、明细导出等数据管理能力；

8. 全部数据核验修正完成后，调用完结接口更新 OCR 识别任务状态，完成单次复核流程。

## 4. 页面核心功能

### 4.1 图片查看与导航功能

实现报销材料全量预览、分类管理与视图自由操控，适配人工复核作业场景：

- 材料分类展示：按 FP（发票）、MX（明细）、BL（病历）、QT（其他）自动归类，结构化展示票据材料；
- 图片导航能力：展示当前图片序号与总数量，支持缩略图快速切换、缩略图区域折叠展开；
- 视图缩放：支持工具栏按钮、鼠标滚轮缩放，缩放区间 0.2–5 倍；
- 视图变换：支持图片顺时针/逆时针 90° 旋转、鼠标拖拽平移、一键复位初始视图；

### 4.2 费用明细查看与编辑功能

右侧结构化表格支撑全维度明细校对与数据修正，适配医保费用核算规则：

- 行内编辑：项目名称、单价、数量支持实时行内修改，无需弹窗跳转；
- 自动核算：修改单价、数量后，自动按 `金额=单价×数量` 重算金额，统一保留两位小数；
- 明细管理：弹窗新增费用明细、二次确认删除，区分未落库临时数据与已落库正式数据，差异化处理删除逻辑；
- 数据统计：实时统计明细总条数、费用合计总金额；
- 数据导出：支持一键导出当前受理单全部费用明细，用于归档与对账。

### 4.3 图文联动高亮功能

基于后端返回的 OCR 原始坐标数据 `posLeftX、posTopY、posRightX、posBottomY`，前端统一封装为坐标对象，实现原图与表格数据精准联动。

通过尺寸比例换算，完成原始图像坐标到页面展示坐标的映射：

```
scaleX = 图片显示宽度 / 图片原始宽度
scaleY = 图片显示高度 / 图片原始高度
显示坐标 = 原图坐标 × 缩放比例
```

用户悬停或点击表格行时，自动完成坐标换算、叠加绿色高亮框、滚动居中展示识别区域，窗口尺寸、分栏尺寸变更后自动刷新高亮位置。图片与高亮层共用变换容器，缩放、旋转、拖拽全程同步，无偏移错位。

### 4.4 Canvas 局部裁剪预览

复用 OCR 识别坐标，通过 Canvas API 对票据局部区域进行裁剪，转换为 Base64 缩略图悬浮展示在表格旁。无需切换左右视图，大幅降低审核人员视线切换成本，提升批量复核效率。

### 4.5 数据质量校验与状态可视化

页面加载完成后自动执行全量数据规则校验，拦截异常核算数据：

- 校验单价、数量、金额数值合法性，拦截非有效数字；
- 禁止负数单价，拦截零数量异常金额；
- 校验人工计算金额与 OCR 识别金额误差，控制误差不超过 0.01；

通过多色样式区分业务状态，直观展示复核进度与数据质量：

| 业务状态     | 页面展示样式 |
| ------------ | ------------ |
| 数据计算异常 | 红色标红     |
| 已人工对照   | 绿色标识     |
| 未对照条目   | 黄色标识     |
| 当前选中行   | 蓝色高亮     |
| 当前悬停行   | 阴影突出效果 |

### 4.6 自适应工作台布局

- 双栏布局：左侧图片预览区、右侧费用表格编辑区，适配工作台作业模式；
- 可拖拽分栏：中间分割条支持拖拽调整宽度，约束左栏宽度 28%–72%，防止布局错乱；
- 全屏适配：支持页面全屏展示，通过 `postMessage` 与父门户通信，自动收起/恢复导航栏；
- 自适应刷新：窗口大小、分栏宽度变化后，自动重算图片尺寸与高亮坐标。

## 5. 技术实现亮点

### 5.1 声明式状态驱动，数据视图高度统一

区分基础可变状态与派生计算状态，`data` 存储原始业务状态，`computed` 统一处理派生逻辑，包含总金额统计、图片分组、分栏样式、图片变换样式、表格滚动配置等。摒弃 AngularJS 大量手动监听、DOM 同步逻辑，视图完全由数据驱动，逻辑更清晰、维护成本更低。

### 5.2 图片索引分层管理，杜绝切换错乱

通过原始全量图片列表与分类视图列表分层设计，保留每条图片的 `globalIndex` 全局索引，解决分类展示场景下局部索引与全局索引混淆问题，保证任意分类下的图片切换精准无误。

### 5.3 自研 OCR 空间坐标映射模型

构建「结构化费用数据 + 原始图像坐标」标准化数据模型，实现原始图像坐标系到前端可视画布坐标系的自动换算与投影，打通图像识别数据与业务审核数据的可视化关联，是页面核心业务技术创新点。

### 5.4 CSS Transform 统一图像变换，性能更优

所有图片缩放、旋转、平移操作均基于 `transform` 实现，不频繁修改 DOM 宽高、定位属性，减少浏览器重排重绘。图像与高亮覆盖层共用变换规则，保证视图变换全程同步无偏差。

### 5.5 Canvas 轻量化能力扩展

基于现有 OCR 坐标数据，前端独立实现局部图像裁剪预览，无需后端改造即可优化审核交互体验，低成本实现功能增值。

### 5.6 渐进式重构，低风险兼容旧体系

通过路由参数、`postMessage` 实现与 AngularJS 旧门户的双向兼容，保留原有多页签、菜单跳转、全屏布局能力。实现单页面 Vue 现代化重构，无需整体替换老旧门户体系，适配大型医保系统渐进式迁移方案。

### 5.7 完整组件生命周期资源管控

严格遵循 Vue 生命周期规范，挂载阶段注册窗口监听、鼠标事件、定时器，销毁阶段统一清理所有全局监听与定时任务，同步恢复父门户布局状态，有效规避内存泄漏问题。

## 6. AngularJS 迁移 Vue 重构核心价值

### 6.1 架构升级：从臃肿控制器到组件化封装

旧 AngularJS 代码所有业务逻辑堆积在 Controller 和 `$scope`，代码耦合严重、边界模糊。重构后收敛为 Vue 单文件组件，模板、样式、业务逻辑、状态管理高度内聚，职责边界清晰，便于迭代维护。

### 6.2 范式升级：命令式操作转为声明式渲染

依托 Vue 内置指令与双向绑定，替代 AngularJS 繁杂的手动 DOM 同步、状态更新逻辑，视图由数据自动推导，减少人工编码带来的兼容性 Bug。

### 6.3 性能升级：摆脱全量脏检查机制

利用计算属性惰性缓存特性，替代 AngularJS 多层 `$watch` 监听与 `$digest` 脏检查，减少无效渲染与性能消耗，复杂页面性能更稳定。

### 6.4 异步升级：Promise 标准化异步流程

统一封装 Promise 风格请求方法，替代老旧 `$http` 回调嵌套写法，异步链路清晰，便于统一封装加载状态、异常捕获、请求拦截。

### 6.5 迁移价值：低风险渐进式迭代

优先重构核心高频业务页面，完全兼容原有接口、业务流程、门户交互，不破坏现有系统体系，适合大型政企医保系统分阶段、低风险技术栈迁移。

## 7. 现存技术问题与缺陷

### 7.1 组件职责臃肿，耦合度高

当前单文件代码量近 1900 行，同时承载图片预览、缩略图导航、表格编辑、坐标换算、Canvas 绘图、接口请求、门户通信、分栏布局等多重职责，属于典型的旧架构逻辑平移，未完成模块化拆分，长期维护难度大。

### 7.2 路由监听采用低效轮询机制

通过定时器轮询监听路由地址变化，触发页面整页刷新，且定时器未保存引用，组件销毁无法清理，存在内存泄漏风险。

### 7.3 跨窗口消息监听存在安全隐患

`postMessage` 使用匿名函数监听，无法在组件销毁时解绑；消息接收未校验域名来源、采用通配符匹配，存在恶意消息注入风险。

### 7.4 简易防抖策略导致数据丢失

固定 500ms 冷却期直接丢弃窗口期内所有请求，用户快速切换图片时，易出现视图已更新、表格数据未同步的问题，无法适配高频切换场景。

### 7.5 并发请求存在响应覆盖风险

快速切换图片会并行发起多条请求，旧请求延迟返回时，会覆盖最新图片数据，导致图文数据不匹配。

### 7.6 业务状态字段映射缺失

对照状态判断依赖 `medListCode` 字段，但数据请求时未完成字段映射，导致所有条目默认判定为未对照，状态展示异常。

### 7.7 坐标合法性判断逻辑不严谨

通过空值判断坐标有效性，当原始坐标数值为 0 时会被误判为无效坐标，导致部分识别区域无法高亮展示。

### 7.8 Canvas 裁剪存在主线程性能压力

表格行每次悬停都会重建 Canvas、重绘图像、生成 Base64，高频操作下会占用主线程资源，存在卡顿、内存堆积风险。

### 7.9 冗余闲置变量过多

`mountTimer`、`navigationGuard` 等状态变量定义未落地业务逻辑，代码冗余、可读性差。

### 7.10 无障碍访问能力缺失

图片操作控件使用普通行内标签，不支持键盘聚焦与快捷键操作，分割条缺少键盘适配，无法满足无障碍访问规范。

## 8. 项目总结

本次改造完成 AngularJS 老旧页面向 Vue2 现代化组件的完整迁移，构建了**票据图像、OCR 坐标、结构化费用数据**三位一体的可视化复核模型，实现图片智能操控、图文联动校对、数据智能核算、异常状态预警、批量数据管理等核心能力。

项目采用渐进式重构方案，完全兼容原有门户体系与业务流程，以极低的改造风险完成技术栈升级，有效提升医保票据人工复核的作业效率与数据准确性。

当前页面已满足线上业务稳定运行要求，但仍存在组件耦合、请求机制不严谨、性能细节不足等问题。后续将通过模块化拆分、稳定性治理、性能优化、技术升级四轮迭代，将页面从“可用的迁移版本”优化为“高可用、高可维护、高性能”的标准化业务组件，支撑医保复核业务长期迭代升级。
